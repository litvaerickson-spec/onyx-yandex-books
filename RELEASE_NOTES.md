# Release Notes — Яндекс Книги Lite v1.5.20-beta

> [!NOTE]
> **Статус выпуска:** Предварительная бета-версия (Beta / Preview).  
> Данная сборка устраняет критический сбой (*«В приложении Яндекс книги произошла ошибка»*) при перелистывании страниц книги (тапом по экрану и нажатием физических боковых кнопок), внедряет самовосстановление схемы SQLite (Self-Healing Schema Auto-Migration) для таблиц прогресса чтения и очереди синхронизации, инкрементирует версию БД (`DATABASE_VERSION = 8`) и обеспечивает 100% отказоустойчивость UI потока ридера.

**Целевые платформы:** Onyx Boox Darwin 7, Darwin 6 (Carta Plus 300 DPI), Darwin 1 (Android 4.2.2 Jelly Bean, API 17, Rockchip RK3026), Darwin 3, 5 (Android 4.4.4 KitKat, API 19, Freescale i.MX6), Onyx Boox Livingstone, Poke, Nova, Note, Tab, Leaf, Page, Palma и все электронные книги на базе Android с экранами E-Ink Carta.

## 🚀 Основные исправления и улучшения в версии 1.5.20-beta

### 1. Устранение аварийного завершения ридера при перелистывании страниц
- **Причина сбоя:** При листании страниц (как тапом по сенсорному экрану, так и физическими боковыми кнопками корпуса устройства) флаг взаимодействия `userHasInteracted` выставлялся в `true`, после чего метод `renderCurrentPage()` немедленно инициировал вызов `saveProgress()`. В версиях с `v1.5.15-beta` по `v1.5.19-beta` из-за вызова `ALTER TABLE` до создания таблицы в `createTables` и отсутствия инкремента `DATABASE_VERSION`, таблица SQLite `progress` не содержала колонку `cfi`. При попытке сохранения `progress` выбрасывалось исключение `android.database.sqlite.SQLiteException: table progress has no column named cfi`, которое не перехватывалось и роняло приложение.
- **Инкремент версии базы данных:** В `DatabaseHelper.java` версия схемы обновлена до `DATABASE_VERSION = 8`.
- **Полноценный DDL таблиц:** Таблицы `progress`, `sync_queue`, `books` и `bookmarks` теперь изначально создаются со всеми обязательными полями (`document_uuid TEXT`, `cfi TEXT`, `created_at INTEGER`, `timestamp INTEGER`).

### 2. Механизм самовосстановления схемы базы данных (Self-Healing Schema Auto-Migration)
- В `DatabaseHelper.java` реализован метод `ensureSchemaMigration(SQLiteDatabase db)`.
- Авто-миграция вызывается не только в `onCreate()` и `onUpgrade()`, но и при каждом открытии базы в `onOpen()`. Это гарантирует, что даже на устройствах, где обновление произошло без вызова `onUpgrade()`, схема мгновенно и прозрачно достраивается до актуального состояния.
- Методы `saveProgress()` и `enqueueOfflineProgress()` защищены двухэтапным fallback: при возникновении любого сбоя структуры таблицы ридер на лету применяет миграцию схемы и повторно фиксирует прогресс чтения без потери данных.

### 3. Тотальная изоляция UI потока ридера (Crash-Proof UI Thread)
- В `ReaderActivity.java` все методы перелистывания и сохранения (`saveProgress()`, `renderCurrentPage()`, `flipPageForward()`, `flipPageBackward()`, `autoSaveRunnable` и `dispatchKeyEvent()`) полностью защищены блоками `try-catch (Throwable t)`.
- Никакие сбои базы данных или сетевого стека больше не прерывают сеанс чтения и не вызывают системное диалоговое окно ошибки.

### 4. Комплексная верификация и тестирование
- **46 автоматических тестов ядра (`verify_core_logic.py`):** Добавлен `[ТЕСТ 46]`, включающий физическое тестирование SQLite через in-memory БД, эмуляцию старой поврежденной схемы, проверку авто-миграции, верификацию try-catch изоляции всех методов листания и прогресса, а также проверку версионирования `v1.5.20-beta` (versionCode 53).
- **Тестовая матрица на 4 виртуальных машинах (`test_dual_configuration_matrix.py`):** Проверена работа DEX-байткода и графического рендеринга на профилях Darwin 1, 3, 5, 6 — 100% тестов пройдены успешно.
