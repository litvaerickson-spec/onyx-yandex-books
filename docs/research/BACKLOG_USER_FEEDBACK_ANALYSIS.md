## 📐 Проблема 1: Выравнивание текста по ширине («справа текст отображается волной»)

### 1.1. Симптоматика
Пользователь обратил внимание, что правый край текста в процессе чтения не выровнен по границе экрана (рваный правый край, «волна»), и в интерфейсе отсутствует очевидная настройка для включения выравнивания по ширине (Justify).

### 1.2. Корневые причины в кодовой базе
Аудит репозитория выявил комплекс из четырёх взаимосвязанных причин:

1. **Отсутствие элемента управления в интерфейсе:**
   - В классе `TypographyConfig.java` (строка 33) параметр `isJustifyEnabled = true` объявлен и имеет геттер/сеттер.
   - Однако в `AppSettings.java` **нет ключа SharedPreferences** для сохранения состояния выравнивания (в отличие от `KEY_HYPHENATION` для переносов).
   - В меню настроек чтения (`activity_reader.xml`, вкладка «Формат») и в коде `ReaderActivity.java` **полностью отсутствует кнопка/переключатель** режима выравнивания. Пользователь физически не может изменить или принудительно включить выравнивание через интерфейс.

2. **Принудительный сброс на левое выравнивание из-за стилей книги (EPUB CSS):**
   - В `TextPaginator.java` (строки 560–568) логика выравнивания блока текста реализована так:
     ```java
     private int resolveAlignment(EpubFormatting.ParsedBlockHeader header, TypographyConfig config) {
         if (header.align == 'C') return ALIGN_CENTER;
         if (header.align == 'R') return ALIGN_RIGHT;
         if (header.align == 'L') return ALIGN_LEFT; // <-- ПРИОРИТЕТ CSS КНИГИ
         if (header.role >= '1' && header.role <= '6') return ALIGN_CENTER;
         if (header.role == 'E') return ALIGN_RIGHT;
         if (header.role == 'N') return ALIGN_LEFT;  // <-- БЛОКИ БЕЗ ОТСТУПА ПРИНУДИТЕЛЬНО ВЛЕВО
         return config.isJustifyEnabled() ? ALIGN_JUSTIFY : ALIGN_LEFT;
     }
     ```
   - В парсере стилей `EpubFormatting.java` (строка 236), если файл стилей книги содержит правило `text-align: left` (что очень часто встречается в издательских верстках для тегов `<p>`, `.text`, `.body`), заголовок блока получает `header.align = 'L'`. Это на 100% переопределяет глобальную настройку `isJustifyEnabled()`, заставляя движок рендерить абзацы по левому краю с рваной «волной» справа.

3. **Сброс выравнивания для первых и специальных абзацев (`role == 'N'`):**
   - В `EpubFormatting.java` (строки 985, 996), если абзац имеет нулевой отступ первой строки (`text-indent: 0` или класс `.noindent`, `.first`), ему присваивается роль `'N'`.
   - В `TextPaginator.java` строка 566 безусловно возвращает `ALIGN_LEFT` для всех блоков с ролью `'N'`, лишая их выравнивания по ширине.

4. **Защитный порог растяжения межсловных пробелов:**
   - В `TextPaginator.java` (строка 632) в методе `buildLine`:
     ```java
     float delta = targetWidth - actualWidth;
     int spaceCount = lineWords.size() - 1;
     if (delta > 0f && delta < targetWidth * 0.45f && spaceCount > 0) {
         wordSpacing = delta / spaceCount;
     }
     ```
   - Если строка содержит длинные слова, а переносы отключены (или слово не разбилось словарём), свободное пространство в конце строки `delta` может превысить 45% ширины экрана. В этом случае алгоритм считает растяжение пробелов типографическим браком («эффект белых рек») и оставляет `wordSpacing = 0f`. В результате строка отрисовывается без растяжения (с волной справа).

### 1.3. План реализации решения (для будущей версии)
1. **Интерфейс и настройки:**
   - Добавить в `AppSettings.java` параметр `TEXT_ALIGNMENT` (режимы: `JUSTIFY` — по ширине, `LEFT` — по левому краю, `ORIGINAL` — по стилям книги).
   - В диалог/панель настроек чтения («Формат») добавить переключатель выравнивания с понятной иконкой и текстовым лейблом.
2. **Логика пагинатора (`TextPaginator`):**
   - Реализовать режим «Игнорировать принудительное выравнивание стилей книги»: если пользователь выбрал «По ширине», то обычные текстовые абзацы (`role == 'P'` и `role == 'N'`) форматируются через `ALIGN_JUSTIFY`, даже если в CSS книги прописан `text-align: left`.
   - Исключение оставлять только для явно центрированных заголовков (`role >= '1' && role <= '6'`), эпиграфов и стихов (`align == 'C'` / `align == 'R'`).
3. **Оптимизация переносов:**
   - Убедиться, что при включенном выравнивании по ширине активны мягкие переносы (Hyphenation), минимизирующие появление пустот более 45%.

## 🔒 Проблема 2: Отображение чужих цитат («в цитатах отображаются чужие цитаты»)

### 2.1. Симптоматика
Пользователь открывает раздел «Цитаты» для книги и видит список цитат и заметок, созданных посторонними пользователями сервиса «Яндекс Книги», а не только свои собственные.

### 2.2. Корневые причины в кодовой базе
Аудит сетевого и БД-слоя выявил критическую ошибку в выборе эндпоинта и отсутствии валидации авторства:

1. **Неверный эндпоинт API (публичный фид вместо профиля):**
   - В `ReaderActivity.java` (строка 3601) при открытии книги вызывается метод:
     ```java
     apiClient.getBookQuotes(bookUuid, new YandexBooksApiClient.ApiCallback<List<Quote>>() { ... });
     ```
   - В `YandexBooksApiClient.java` (строка 2929) метод сформирован следующим образом:
     ```java
     String url = BASE_URL + "/books/" + bookUuid + "/quotes?per_page=100";
     Request request = createAuthRequestBuilder(url).get().build();
     ```
   - В архитектуре API Bookmate / Яндекс Книги эндпоинт `GET /api/v5/books/{uuid}/quotes` является **публичной социальной лентой книги** — он возвращает до 100 публичных цитат, оставленных **всеми читателями сервиса** со всего мира.
   - Персональные цитаты конкретного авторизованного пользователя в данном API располагаются по эндпоинту `GET /api/v5/profile/quotes?book_uuid={uuid}` (или `GET /api/v5/profile/quotes` с фильтрацией по книге).

2. **Отсутствие проверки владельца при десериализации JSON:**
   - В `YandexBooksApiClient.java` (строки 2960–2989) метод `parseQuotesJson`:
     ```java
     for (int i = 0; i < arr.length(); i++) {
         JSONObject obj = arr.optJSONObject(i);
         ...
         Quote q = new Quote();
         q.bookUuid = bookUuid;
         q.quoteUuid = obj.optString("uuid", obj.optString("id", ""));
         q.text = text.trim();
         ...
         result.add(q);
     }
     ```
   - Парсер вообще не проверяет поля принадлежности: `user_id`, `user_uuid`, `user.login` или булевый флаг `is_mine` / `mine`. Все 100 цитат чужих людей упаковываются в объекты `Quote` как равноправные.

3. **Засорение локальной базы данных SQLite:**
   - В `ReaderActivity.java` (строка 3605) полученный список чужих цитат передаётся в БД:
     ```java
     dbHelper.upsertCloudQuotes(bookUuid, remoteQuotes);
     ```
   - Метод `DatabaseHelper.upsertCloudQuotes` сохраняет их в локальную таблицу `quotes`.
   - В результате:
     - Все чужие цитаты попадают в локальную вкладку «Цитаты» книги.
     - Метод `refreshCanvasChapterQuotes` считывает цитаты из БД и передает их в `readerCanvas.setChapterQuotes(qList)`.
     - Дисплейный компонент `ReaderCanvasView` отрисовывает желтые маркеры и подчеркивания в тексте книги по чужим координатам, создавая визуальный шум чужих пометок.

### 2.3. План реализации решения (для будущей версии)
1. **Переключение API-эндпоинта:**
   - Перевести запрос на эндпоинт профиля пользователя: `GET /api/v5/profile/quotes?book_uuid={bookUuid}`.
   - В качестве резервного механизма: если используется общий эндпоинт, жестко фильтровать элементы по флагу `is_mine == true` или совпадению `user.uuid` / `user.login` с текущим авторизованным аккаунтом.
2. **Разделение сущностей в базе данных и UI:**
   - При необходимости поддержки публичных цитат (как социальной функции Букмейта) выделить для них отдельную вкладку: «Мои цитаты» vs «Цитаты читателей».
   - В текст на холсте рендерить подсветку **только** для личных цитат владельца устройства (`is_mine == true`).
3. **Механизм очистки (миграция базы данных):**
   - Разработать однократную процедуру санитизации локальной SQLite: удалить цитаты, загруженные из чужих профилей, чтобы избавить пользователей от накопившегося мусора.

## ❓ 3. Наводящие вопросы для пользователя

Для точной фиксации сценариев воспроизведения и утверждения будущих требований подготовлены следующие дипломатичные и конкретные вопросы:

### Блок 1: По выравниванию текста (волна справа)
1. **Масштаб проявления:**  
   *«Подскажите, пожалуйста, неровный правый край («волна») наблюдается во всех открываемых книгах или в какой-то одной конкретной? Если в конкретной, напишите её название и автора, чтобы мы могли изучить внутреннюю структуру её стилей.»*
2. **Состояние переносов:**  
   *«Включены ли у вас переносы слов в меню чтения (раздел настроек «Шрифт / Формат» $\to$ пункт «Переносы»)? Если переносы отключены, длинные слова не могут разрываться, из-за чего правый край строки не растягивается во избежание огромных пробелов.»*
3. **Ожидаемый переключатель:**  
   *«Будет ли удобно, если мы добавим в панель настроек явный переключатель: «Выравнивание: По ширине / По левому краю», который будет принудительно выравнивать текст ровным блоком, даже если издатель книги задал свои правила?»*

### Блок 2: По отображению цитат (чужие пометки)
1. **Область отображения:**  
   *«Чужие цитаты видны только в списке в окне «Цитаты» (в меню книги) или они также выделяются маркером/подчеркиванием прямо в тексте на страницах самой книги во время чтения?»*
2. **Наличие личных заметок:**  
   *«Делали ли вы ранее собственные цитаты или закладки в этой книге в мобильном приложении «Яндекс Книги» на смартфоне? Отображаются ли среди чужих записей ваши собственные?»*
3. **Ожидаемое поведение интерфейса:**  
   *«Хотели бы вы в будущем иметь возможность просматривать популярные общественные цитаты других читателей (например, в отдельной вкладке «Цитаты сообщества»), либо в приложении на устройстве должны отображаться СТРОГО и ИСКЛЮЧИТЕЛЬНО только ваши личные заметки?»*
