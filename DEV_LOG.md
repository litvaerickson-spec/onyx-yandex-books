1. **Инициализация проекта**: Создана рабочая директория `01_onyx_yandex_books` с четкой структурой документации (`docs/specs`, `docs/guides`, `docs/research`).
2. **Отказ от WebView**: Зафиксировано строгое решение не использовать Android WebView / Chromium 30. WebView на Android 4.2/4.4 потребляет 150-250 МБ оперативной памяти и неизбежно вызывает OOM (Out Of Memory) на Darwin 3 (512 МБ), а также не обеспечивает чистую постраничную пагинацию. Отрисовка переведена на нативный `Canvas` с потреблением памяти ~15-20 МБ.
3. **Решение проблемы TLS**: Системный криптопровайдер Android 4.x не поддерживает TLS 1.3 и современные шифры Яндекса. В архитектуру заложен `Google Conscrypt` (BoringSSL), инициализируемый первой строкой в `Application.onCreate()`, в связке с `OkHttp 3.12.13`.
4. **Авторизация**: Реализуется механизм OAuth Device Code Flow (приложение генерирует QR-код и 6-значный код, пользователь подтверждает вход на `ya.ru/device` со смартфона или компьютера).
5. **Умная синхронизация**: Зафиксирован алгоритм предотвращения перезаписи прогресса, если пользователь параллельно читал книгу на смартфоне.
6. **Типографика AlReader**: В план добавлен модуль TeX-переносов (Franklin-Liang) для русского и английского языков, инлайн-сноски и поддержка внешних шрифтов.

16. **Версия 1.2.3: Полное решение проблемы с вызовом клавиатуры и вводом в WebView**:
    - **Анализ скриншота пользователя (`media_1790927160801.jpg`)**:
      1. *Пустой QR-код*: На Android 4.4.4 KitKat системный Chromium 30 не поддерживает современные API (Fetch, WebCrypto, WSS), используемые React-скриптами Яндекс Паспорта при десктопном User-Agent. Из-за этого скрипт генерации QR падал, оставляя белое пустое поле.
      2. *Не вызывалась клавиатура*: В разметке `WebView` отсутствовали атрибуты `focusable="true"` и `focusableInTouchMode="true"`. В оболочке Onyx Boox специализированная экранная клавиатура `OnyxIME` игнорирует касания WebView без явного фокуса.
    - **Инженерные решения**:
      - Возвращен стабильный мобильный User-Agent, при котором Яндекс отдает чистую легковесную HTML-форму без тяжелых современных скриптов.
      - Включен фокус на `WebView`: `focusable="true"`, `focusableInTouchMode="true"`, `requestFocus()`, перехватчик `onTouchListener`.
      - В панель управления добавлена кнопка **`[ ⌨️ Клавиатура ]`**, принудительно открывающая экранную клавиатуру через `InputMethodManager.toggleSoftInput()`.
      - В панель управления добавлена кнопка **`[ ✏️ Ввести в поле ]`**, открывающая нативный диалог ввода `AlertDialog`. Введенный номер телефона или логин автоматически вставляется в форму Яндекса через JavaScript-инъекцию и нажимается «Далее».
    - **Обновление версий**:
      - Версия поднята до `1.2.3` (`versionCode="6"`).
      - Предыдущие версии `v1.2.1` и `v1.2.2` удалены.

    - **Фундаментальное открытие механизма отдачи страниц Яндекса**:
      - При отправке User-Agent'ов Chrome 90/120 сервера Яндекса отдают 140 КБ тяжелого React 18 SPA с `<canvas>`, WebCrypto и синтетическими событиями, которые падают на системном Chromium 30 (Android 4.4.4 KitKat) с белым экраном вместо QR и блокировкой клавиатуры.
      - При установке **подлинного User-Agent Android KitKat 4.4.4** (`Mozilla/5.0 (Linux; U; Android 4.4.4; ru-ru; Onyx Darwin Build/KTU84P) AppleWebKit/534.30 (KHTML, like Gecko) Version/4.0 Mobile Safari/534.30`) и параметра `&lang=ru`, сервера Яндекса переключаются в специализированный легковесный режим **Granny / Domik**!
      - В этом режиме Яндекс отдает:
